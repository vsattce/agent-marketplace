# 精简当前改动

仅在用户明确调用本 Skill 后使用。Codex 调用 `$personal-dev:dev-simplify`，Claude Code 调用 `/personal-dev:dev-simplify`；普通请求、引用调用名或讨论 Skill 都不触发它。

## 默认只读建议

先理解完整请求中的执行意图。默认由当前模型只读检查并在聊天中提出建议，等待用户确认后再编辑；用户明确要求直接精简时执行。“先看看”“给建议”或“暂时不要改”等要求优先；引用调用名不构成执行授权。

只处理当前调用指向的项目和任务，不跨项目、不修改全局配置；任务结束或用户明确更换任务后，本 Skill 的约束不继续延用。默认检查当前项目工作区的暂存、未暂存和新增源码；用户指定文件、目录、commit 或差异时，严格限于该范围。只有 Git 不可用或工作区没有差异、且用户没有指定范围时，才询问检查范围，不猜测最近提交或扩大到全项目。用户只调用 Skill 名而未写范围时，先按工作区 diff 检查。可以读取必要的直接调用点来判断影响，但不能借此扩展编辑范围。若混有无法可靠归属的改动，先澄清一次并保留这些改动。

## 候选与边界

只建议能降低真实理解或维护成本的改动，例如没有实际价值的中间层、冗余分支或可安全合并的重复逻辑。衡量可读性、职责与维护成本；不以行数、去重率或代码技巧为目标，也允许结论是无需精简。

无论建议还是执行，都保留已有行为、接口、数据契约、错误处理、安全与权限、事务、调用顺序、外部请求、并发、必要日志和资源生命周期，并避免性能回退。发现 Bug 时单独报告；修 Bug 需要用户明确授权，不能混入精简。无法确认行为等价或验证条件不足的候选项只作为建议，不改动也不声称已验证。

用户明确要求执行或确认建议后，只修改授权范围内可确认安全的部分，运行有助于验证这些改动的检查，并核对最终差异。报告实际改动、验证结果和未验证项。调用本身不扩大 Git、依赖或发布权限；这些操作按目标项目规则和当前任务已有授权处理。

默认由当前模型处理，不自行派生代理或自动调用其他 Skill。只有用户明确选择 `dev-delegate` 时，才将本 Skill 已启用的约束、已确认建议、授权范围和验证条件交给既有委派流程；任何尚待确认的建议仍需等待确认，不能以委派绕过。
