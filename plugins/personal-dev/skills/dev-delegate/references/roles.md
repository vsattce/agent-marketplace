# 角色交接与验收契约

所有角色服从目标项目规则、当前用户授权和本 Skill 的模型选择、修复上限。禁止派生子代理、擅自升级模型、修改全局配置或自行 commit / push。

## 编码代理

主模型提供：

- 工作目录、目标、修改范围、原有用户改动与基线。单个简单任务沿用主 Skill 的精简交接；多任务或确需进度恢复时补稳定任务 ID、`depends_on`、`write_scope` 与并行决定。
- 必要接口、相关调用点、已有关键决策和约束。
- 可逐项判断的验收条件、适当的验证要求。
- 当前阶段、累计修复轮次和必要证据路径；多任务的 ledger 由主模型维护，编码代理不得写入。长期证据才按需使用 `docs/personal-dev/tasks/<task-id>/`，不得要求读取全部聊天历史。

只修改获准的 `write_scope`。需要扩大范围或使用冲突的测试输出、端口等资源时先返回主模型判断，不自行越界；不读取其他 Coder 的讨论，不向 Reviewer 直接发消息。

代理完成实现、自检并按项目规则验证。上下文不足用 `NEEDS_CONTEXT`，确实受阻用 `BLOCKED`，完成但有疑点用 `DONE_WITH_CONCERNS`，其余用 `DONE`。完成声明包含：改动文件、行为变化、实际验证命令与结果、未验证项及理由、疑点。不得用空 TODO / 伪实现冒充完成。

迭代仅执行与改动相关的检查，项目要求或真实风险需要时才跑完整检查。遵守对应运行时约束；不为 Agent 工具安装/切换项目运行时或修改 PATH。

## 独立验收代理

主模型提供同一任务要求、必要接口约束、固定的实际改动证据（含新增文件与未提交改动）、编码报告与验证证据。按 Harness adapter 选择验收策略：Codex 默认同型号 `xhigh`，Claude Code 沿用当前子代理配置。新建区别于全部 Coder 的干净上下文，只读审查；不接收编码思考、完整聊天或讨论过程，不与 Coder 直接交流。疑问只交主模型；需要有副作用的验证时先报告，由主模型按项目授权安排。

主模型冻结验收范围及相关依赖的写入，完全无关任务可继续。合并不可分割功能单元验收时，逐任务给出结论、证据和阻塞项，不合并修复预算。审查期间发现版本变化须报告，不能沿用旧证据宣称新代码通过。

一次审查同时输出：

1. **需求：** `PASS` / `FAIL` / `UNVERIFIED`，逐项识别遗漏、误解、额外实现。
2. **质量与正确性：** `PASS` / `FAIL` / `UNVERIFIED`，检查实际实现、直接调用关系和相关边界。
3. **阻塞项：** 每项给文件/行号、触发条件、实际影响、证据与建议；未确认疑点与确定缺陷分开。
4. **非阻塞建议：** 风格偏好、可选优化与范围外观察单列，不扩大返工。
5. **验证证据：** 检查覆盖真实行为、必要边界和当前代码版本。证据充分则复用，有具体缺口才补针对性检查。未验证项明确说明，不用猜测填成通过。

报告不能只引用编码代理的“测试通过”；核对差异、测试内容及实际输出。简单任务按上述维度简短返回结论、必要证据与未验证项，聚焦验收条件和直接影响即可；相关函数或契约变更时检查直接调用点，实际风险需要时扩大检查。

`UNVERIFIED` 的必要条件未解决前不能接受任务。主模型可核实缺失证据、裁决审查误判或补充需求，不能以沉默或“可能没事”当作通过。

## 修复与复验

主模型一次交回完整阻塞列表及本任务累计轮次。原编码代理修复并补充受影响验证；独立验收代理逐项输出 `ADDRESSED` / `NOT_ADDRESSED`，检查修复引入的问题和直接影响，不再全项目巡查。新的范围外建议不延长循环。

一次修复和一次复验计一轮，初次实现不计；每任务最多两轮，第二轮仍阻塞时全流程停止。子代理无法恢复或重建上下文不重置计数。

主模型在修复派发前预记本轮和 `FIXING`，修复完成记 `REVIEW`；同轮复验不再次加一。恢复先核实原代理和证据，修复已完成则只补复验，不重做同轮修复或清零预算。

## 独立整体终审

仅在主 Skill 第 5 节的条件触发时，由主模型新派区别于全部 Coder 和任务 Reviewer 的只读代理；使用对应 Harness adapter 的终审模型策略，不调用另一个手动 Skill。沿用独立验收的上下文、写入冻结与证据要求。

输入包括已确认的整体需求、必要契约、累计实际改动（含 staged、unstaged、新文件）、各任务验收与验证证据、待处理问题；不提供编码思考、完整聊天或引导其认可主模型结论。重点检查端到端需求、跨任务数据与调用关系、兼容性及本次改动涉及的安全边界，内部实现复用有效验收结论，有具体疑点才展开。

输出整体 `PASS` / `FAIL` / `UNVERIFIED`、有证据的阻塞项、非阻塞建议和必要验证缺口；任务均通过不代表整体通过。阻塞项由主模型归属到相关任务，交原编码代理修复并验证，沿用该任务剩余两轮预算；由终审代理独立复验原问题及影响，不重复整体巡查。无法安全归属、剩余预算耗尽或必要证据未解决时停止并报告，不通过新增终审任务重开预算。

## 主模型整体检查与中断输出

主模型按主 Skill 第 5 节核对整体需求、跨任务联动、范围和最终代码版本，复用已验收的内部实现结论。需要独立整体终审时，整合其结论并核实阻塞项已关闭，不再重复同范围详细审查。普通低风险单任务主要核对需求、范围与版本；具体疑点、后续改动及终审修复只复核受影响部分。

选择/能力不明确、确定缺陷超限或需要用户升级决定时，中断输出：状态与理由、已完成和未完成工作、实际模型/强度、已尝试的方法与证据、继续所需的明确决定。中断不创建额外代理、不擅自接手编码、不宣称验收通过。
