# 角色交接与验收契约

所有角色服从目标项目规则、用户授权及 `SPEC > PLAN > Coder interpretation`，读取同一 SPEC 与执行补正，不改写明确需求或用 SPEC 越权。主模型独占计划、调度与争议裁决；子代理不得再派生、自行升级配置、改全局环境或 commit / push。各角色模型依[子代理模型契约](../../../references/subagent-models.md)。

## 编码代理

使用 worker。交接只传目标项目、SPEC / PLAN 路径与本任务定位、规则、必要接口和基线、用户已有改动、阶段及验证要求；有 Ruling 时提供记录路径与段落并要求读取，单任务也适用。Coder 先读 SPEC、本任务 PLAN 和必要依赖，不复制完整聊天或其他 Coder 讨论。多任务补稳定 task_id、depends_on、write_scope，并行 / ledger 启用时再补相应决定与路径，ledger 仅主模型写。

只在获准 write_scope 内按验收标准实现并自检，不用 TODO / 伪实现代替关键功能。扩大范围、共享验证资源冲突或上下文不足时回主模型裁决，普通细节不转用户问答。遵循项目运行时及验证深度，不为工具安装 / 切换运行时或改 PATH。

返回 DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED，附实际改动、验证命令与结果、未验证项及原因。报告待核实，不等于验收通过；单任务简报，长报告 / 多轮证据用本次目录文件定位交接。

## 独立验收代理

使用 reviewer，新建区别于全部 Coder 的干净只读上下文。提供同一 SPEC / PLAN、Ruling 定位、staged / unstaged / 新文件差异、编码报告与验证证据；先读 SPEC 和补正，不只按未补正的外部 PLAN 验收。检查需求、正确性、直接调用关系和必要质量边界；不写文件、修复、提交或派生代理，有副作用验证交主模型安排 Worker。双方不直接交流，由主模型传递信息。

验收前确认 worker 停止该范围写入；仅并发写入或变化中依赖风险时冻结相关范围，无关安全任务继续。旧版本证据不证明新代码通过。一次返回：

1. 需求符合度 PASS / FAIL / UNVERIFIED：对照 SPEC 检查遗漏、误解及额外实现。
2. 质量与正确性 PASS / FAIL / UNVERIFIED：实际代码、调用关系及必要边界。
3. 稳定 finding_id、SPEC 条款或项目约束、文件 / 行号、触发、影响与直接证据；区分 blocker、建议及未验证疑点。
4. 验证证据是否对应当前代码和真实行为；有效证据可复用，具体缺口才补检查，不只引用 Coder 的“测试通过”。

必要验收项 UNVERIFIED 时补证据或 BLOCKED，不猜 PASS。简单任务聚焦差异、验收与直接影响；不可分割单元可合并验收，仍逐任务保留结论和预算，不绕过依赖顺序。

## 修复与收敛

主模型先按以下规则裁决 finding，再派修复：

| 分类 | 判定与处理 |
| --- | --- |
| 真实 blocker | 违反 SPEC 验收或适用项目 / 安全约束，或有证据的正确性缺陷使任务不可接受；进入修复 |
| 重复问题 | 按根因、触发及影响沿用 finding_id，核实已修 / 仍存，不重置预算 |
| 新发现 | 标 NEW，核实属本任务 SPEC / 必要约束或修复引入，真实 blocker 使用剩余预算 |
| 建议 / 风格偏好 | 无强制规范或实际影响的可选覆盖、优化、可维护性建议不阻塞，不要求反复改写 |
| 超出 SPEC | 拒绝并说明 SPEC 依据，不扩大需求；适用项目 / 安全硬约束不能以 SPEC 未写忽略 |

记录 `Ruling: finding_id — 接受 / 拒绝 / 非阻塞 — 证据与 SPEC 依据 — 影响`，只写已有 ledger 或可写 PLAN 任务段落；外部只读 PLAN 按准备契约用本次 progress.md，保持源文件原样。误判由主模型裁决，不靠双方争论或新增审查席位。

无 blocker 不修复；通常原 Coder 修一次并复验，通过即最终核验，持续有真实 blocker 才继续。初次实现不计；一次修复派发 + 一次独立复验为一轮，每任务最多 3 轮，不是默认做满：

- 返工优先恢复原 Coder，交回全部真实 blocker、文件定位及累计轮次。仅原代理不可恢复、上下文失效或同根因反复无进展时用 fresh coder，交接同一 SPEC / PLAN、当前实现、blocker、历次尝试与证据，保留同一 worker 配置；不按轮次换人。Reviewer 始终独立于全部 Coder。
- 每轮逐项 ADDRESSED / NOT_ADDRESSED，只复核原问题、修复与直接影响，不重扫全项目。新增真实缺陷、同根因问题、换代理、改任务名、恢复或终审都不重开预算；建议、偏好及范围外要求不延长循环。
- 第三轮后主模型做 adjudication / convergence，记录已解决、同根因未变、有进展、新问题、剩余 blocker 和证据裁决。仅剩误判或建议可接受；核心 blocker 未解则 FAILED，必要证据不可得则 BLOCKED。不允许第 4 轮，也不因耗尽轮次降级缺陷或放行。

派发修复前预记 fix_rounds=1/2/3 与 FIXING，返回记 REVIEW，同轮复验不加一；有 ledger 写 ledger，否则在可写 PLAN 简记轮次、阶段、代理 ID 与证据，只读 PLAN 按需用 progress.md。中断先核实实际阶段，完成修复只补复验，不重发仍运行的工作或清零计数。

FAILED / BLOCKED 仅隔离真实依赖链与具体风险范围，其他安全任务继续；仅必需执行能力整体缺失或风险覆盖全部剩余路径时全局停止，不由主模型接手编码绕过。发生依赖风险时先读[编排契约](orchestration.md#任务失败隔离)，记录原因、配置、尝试、证据、受影响依赖、可继续任务及解除条件，保留未完成文件与记录。

## 整体检查与结果

主模型的最终 fresh verification 和独立 Final Reviewer 五类触发条件以[主入口第 5 节](../SKILL.md#5-主模型整体检查与条件-final-reviewer)为准，失败或阻塞不省略整体检查。

触发终审时，用同一 reviewer 配置，另建区别于全部 Coder 和任务 Reviewer 的干净只读上下文。输入整体 SPEC / PLAN、Ruling、累计差异、任务验收、验证证据及待办；冻结所审范围，核对端到端行为、跨任务契约和触发风险。返回 PASS / FAIL / UNVERIFIED、真实 blocker、建议与证据缺口；有效内部结论可复用，具体疑点才展开。发现交主模型裁决，代码修复交 Coder，归属原任务剩余预算，不新建“终审任务”获新预算。

判断困难时 Reviewer 说明已查证据和缺口，主模型先补材料，继续同一 reviewer 复核问题及影响，不升级 effort；必要结论仍不可得则只阻塞相关任务。最终状态、未完成项汇总与授权收尾依主入口，不能宣称全部验收通过。
