# 委派开发与独立验收

Only use when explicitly invoked by the user. Codex 使用 `$personal-dev:dev-delegate`，Claude Code 使用 `/personal-dev:dev-delegate`；普通开发请求不自动触发本 Skill。

任务记录和临时产物按需遵循[任务产物位置](../../references/artifacts.md)；普通小任务只在交接消息中说明，不强制创建文档。

当前对话主模型安排任务和最终整体检查；编码与验收由不同的独立 subagent 执行。Codex 使用同型号 Luna，默认编码 `xhigh`、独立验收 `max`（最强）；Claude Code 沿用当前子代理模型与思考配置。用户可分别指定本次编码与验收的思考强度，明确指定的角色优先使用用户值，未指定的角色保留默认策略；按对应 adapter 核验支持后直接执行，无需再次确认强度。目标是减少主模型的实现与逐项审查负担，不承诺固定费用、额度或总 token 降幅。

## 1. 先确定 Harness 与委派策略

读取目标项目规则与相关实现，从当前会话确认真实 Harness，不能从模型品牌猜客户端。Codex 读取 [Codex adapter](../../references/codex.md)，Claude Code 读取 [Claude adapter](../../references/claude.md)；未知 Harness 或其他平台 `BLOCKED / UNSUPPORTED AGENT`。

按对应 adapter 完成工具、独立上下文、模型与思考配置预检。Codex 用随本 Skill 的 `scripts/select_models.py` 校验当前工具名单，`READY` 才可继续；Claude 用原生 `Agent`，默认不覆写模型或思考配置，不运行 Codex helper，也不因缺少 Python 或 Codex 参数而阻塞。

必需能力缺失时集中给出具体原因与继续所需信息，不安装依赖、修改全局配置或由主模型代做来绕过。

## 2. 展示后直接执行

预检成功后，**在任何代码编辑和编码派发之前**按 adapter 展示编码 / 验收两行。Codex 显示 helper 返回的实际值，例如：

```text
编码模型：gpt-6-luna｜思考强度：xhigh
验收模型：gpt-6-luna｜思考强度：max
```

这是输出形式示例，不是固定型号。Claude 显示“Claude Code 子代理默认 / 沿用当前配置”，实际 ID 或强度未确认时标 `UNKNOWN`。成功预检后直接执行，不额外询问是否开始；型号或强度变化时先重新显示。中断时输出 `BLOCKED：<具体理由>`、已有成果及继续所需信息；不能输出成功启动提示。

## 3. 安排任务并派发

按可独立验证的功能或修复点拆分，同类小改动合并，不机械按文件分代理。主模型解决关键方案和接口判断，把具体实现交给编码代理；默认一次只有一个写入代理。相关信息不足时由主模型补齐，影响业务或授权边界的缺口交用户决定。

派发前读取 [角色交接与验收契约](references/roles.md)。按当前 Harness adapter 调用原生委派工具，新任务使用干净上下文，不复制整段聊天。提供工作目录、任务范围、接口约束、验收条件与验证要求。所有子代理禁止继续派生代理。

简单任务在派发消息中交接即可。多步骤或长任务仅在需要跨步骤恢复或保留验收证据时，在 `docs/personal-dev/tasks/<task-id>/` 建立轻量任务记录；设计、计划、进度和验收文件按实际需要创建，包含需求、实际模型、代理身份、验收状态、修复次数、改动基线和证据位置。短期日志及原始测试输出可放在 `.agent-tmp/tasks/<task-id>/`，不记录敏感信息。上下文压缩后先恢复已建立的记录，禁止重复开发已完成任务或清零修复计数。

派发前记录原有 tracked / staged / untracked 改动；保留用户已有内容。编码代理不 commit / push。审查必须覆盖本任务 staged、unstaged 和新文件；`BASE..HEAD` 只包含已提交改动，不能作为未提交任务的全部证据。已有用户改动与任务改动无法区分时先澄清，不能重置或丢弃。

## 4. 独立严格验收与有限返工

编码代理自检和报告后，由主模型派发**另一个干净上下文**的验收代理。Codex 为同型号、默认 `max`；Claude 沿用相同原生默认策略。同时检查需求符合度、正确性、相关调用点、代码质量及验证证据。严格意味着有依据地发现实际阻塞项；风格偏好和范围外优化仅建议，不扩大需求。

首轮尽量完整汇总阻塞项。报告中的“完成 / 测试通过”是待核实声明，审查实际代码与证据。证据足以覆盖当前代码时复用；有具体疑点再做针对性验证，按项目规则与真实风险决定深度。

主模型协调结果，必要时裁决有证据的误判，不重复逐项全面审查。实际阻塞项交原编码代理修复，保持编码强度；优先用本轮工具支持的 follow-up/resume 接口，不假设可以原地改变型号或强度。代理无法恢复时才重新提供任务与历史尝试。

**初次实现不计轮次；一次修复加一次独立复验是一轮，每个任务最多两轮。**复验只检查原问题、修复及其影响。跨代理、任务重命名、上下文恢复和最终检查不重置计数。第二轮仍有实际阻塞项时停止整个流程，报告问题、尝试、证据和已有成果；等用户决定升级。不得自动升级、由主模型接手编码或把真实缺陷标为完成。

## 5. 主模型最终整体检查

所有任务通过后，当前主模型对实际累计改动做一次完整整体检查：需求覆盖、跨任务接口联动、遗漏、验证与范围外改动。独立验收报告不能替代这一步。终审发现问题交回编码代理，使用相应任务剩余修复次数；修复后只复核受影响范围。未明确归属的新问题作为新发现记录，不能给同一问题重开预算。

通过后按目标项目授权与规则执行 Git 收尾，本 Skill 不额外授予提交、推送、发布或全局写入权限。最终报告实际结果、验证与未完成项。执行中定期给出简短进度，不能只在后台派发后长时间无输出。
