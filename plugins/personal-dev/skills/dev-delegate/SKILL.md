# 委派开发与独立验收

Only use when explicitly invoked by the user. Codex 使用 `$personal-dev:dev-delegate`，Claude Code 使用 `/personal-dev:dev-delegate`；普通开发请求不自动触发本 Skill。

定位为轻量、确定性的 Subagent-Driven Development orchestrator。任务记录遵循[任务产物位置](../../references/artifacts.md)；单个简单任务不创建 ledger，多任务使用临时进度记录，不强制长期文档。不引入 workflow engine、自动 worktree / merge、Agent Teams 或后台服务。

当前对话主模型安排任务和最终整体检查；编码与验收由不同的独立 subagent 执行。Codex 使用同型号 Luna，默认编码 `high`、独立验收 `xhigh`；Claude Code 沿用当前子代理模型与思考配置。用户可分别指定本次编码与验收的思考强度，明确指定的角色优先使用用户值，未指定的角色保留默认策略；按对应 adapter 核验支持后直接执行，无需再次确认强度。目标是减少主模型的实现与逐项审查负担，不承诺固定费用、额度或总 token 降幅。

## 1. 先确定 Harness 与委派策略

读取目标项目规则与相关实现，从当前会话确认真实 Harness，不能从模型品牌猜客户端。Codex 读取 [Codex adapter](../../references/codex.md)，Claude Code 读取 [Claude adapter](../../references/claude.md)；未知 Harness 或其他平台 `BLOCKED / UNSUPPORTED AGENT`。

主模型先按目标项目规则评估复杂度、风险与模型适配，补齐关键设计和验收条件；默认模型仍不足以承担任务时，按 adapter 的精确型号覆写与授权规则处理，不把提高思考强度当作模型能力升级。需要第 5 节的独立整体终审时，一并核验当前会话的精确型号、实际思考强度及其来源，作为终审上限。

按对应 adapter 完成工具、独立上下文、模型与思考配置预检。Codex 用随本 Skill 的 `scripts/select_models.py` 校验编码、任务验收及已触发的整体终审，`READY` 才可继续；Claude 用原生 `Agent`，编码与任务验收默认不覆写模型或思考配置，整体终审按 adapter 核验预算，不运行 Codex helper，也不因缺少 Python 或 Codex 参数而阻塞。

必需能力缺失时集中给出具体原因与继续所需信息，不安装依赖、修改全局配置或由主模型代做来绕过。

## 2. 展示后直接执行

预检成功后，**在任何代码编辑和编码派发之前**按 adapter 展示编码 / 验收两行。Codex 显示 helper 返回的实际值，例如：

```text
编码模型：gpt-6-luna｜思考强度：high
验收模型：gpt-6-luna｜思考强度：xhigh
```

这是输出形式示例，不是固定型号。Claude 的编码与任务验收显示“Claude Code 子代理默认 / 沿用当前配置”，实际 ID 或强度未确认时标 `UNKNOWN`。需要独立整体终审时额外显示实际终审型号、思考强度与会话上限；不能核验上限或有效派发设置时停止。成功预检后直接执行，不额外询问是否开始；型号或强度变化时先重新显示。中断时输出 `BLOCKED：<具体理由>`、已有成果及继续所需信息；不能输出成功启动提示。

## 3. 安排任务并派发

按可独立验收的完整功能或修复点拆分，同类小改动合并。同一功能的 DTO、Service、Controller 与前端调用优先交给一个编码代理完成后统一验收；确有独立交付边界或规模需要时才拆开，不机械按文件或技术层分代理。主模型解决关键方案和接口判断，把具体实现交给编码代理。相关信息不足时由主模型补齐，影响业务或授权边界的缺口交用户决定。

单个简单任务按下段精简交接。多任务、复杂或高风险任务，派发前读取[任务编排与进度恢复](references/orchestration.md)，完成计划冲突预检；多任务或确需进度恢复时，再明确每项 `task_id`、目标、`depends_on`、`write_scope`、`can_parallel`。拆开的依赖任务通过独立验收且契约确定后才能启动下游。默认一个写入代理；无依赖、写入不重叠、无变化中的共享契约、工具支持且合并风险低时才允许两个，最多三个，并受实际槽位限制。无法确认安全并发就串行，不增加基础设施。

派发前读取 [角色交接与验收契约](references/roles.md)。按当前 Harness adapter 调用原生委派工具，新任务使用干净上下文，不复制整段聊天。提供工作目录、任务范围、接口约束、验收条件与验证要求。所有子代理禁止继续派生代理。

边界明确的文案、样式或局部低风险修复，在派发消息中交接目标、修改范围、必要约束、验收条件、最小验证与原有改动即可；默认单写、无依赖，不额外填写多任务编排字段、建 ledger 或生成报告文件。涉及公共契约、数据库、安全或并发边界的任务按真实风险处理。

拆出两个及以上开发任务（含串行依赖任务）时，主模型在首次派发前创建 `.agent-tmp/dev-delegate/<task-id>/progress.md`，确认 Git 忽略；记录任务、代理实际身份与模型、状态、修复轮次和必要证据，每次阶段变化及时更新。恢复时先读当前任务 ledger，再核对真实代码、Git 与代理状态；不重复派发已完成任务，不清零计数。长期设计或验收证据才按需放入 `docs/personal-dev/tasks/<task-id>/`。

派发前记录原有 tracked / staged / untracked 改动；保留用户已有内容。编码代理不 commit / push。审查必须覆盖本任务 staged、unstaged 和新文件；`BASE..HEAD` 只包含已提交改动，不能作为未提交任务的全部证据。已有用户改动与任务改动无法区分时先澄清，不能重置或丢弃。

## 4. 独立严格验收与有限返工

编码代理自检和报告后，由主模型派发**另一个干净上下文**的验收代理。Codex 为同型号、默认 `xhigh`；Claude 沿用相同原生默认策略。同时检查需求符合度、正确性、相关调用点、代码质量及验证证据；简单任务聚焦验收条件、实际差异和直接影响，验证深度按项目规则与真实风险决定。严格意味着有依据地发现实际阻塞项；风格偏好和范围外优化仅建议，不扩大需求。

验收期间冻结被审查范围及相关依赖的写入。独立任务可分别验收；不可分割的功能单元可合并验收，但逐任务保留结论和预算。验收只接收任务要求、接口约束、实际改动、编码报告与验证证据；不接收完整思考或聊天历史，Coder 与 Reviewer 不直接讨论，由主模型传递必要信息。

首轮尽量完整汇总阻塞项。报告中的“完成 / 测试通过”是待核实声明，审查实际代码与证据。证据足以覆盖当前代码时复用；有具体疑点再做针对性验证，按项目规则与真实风险决定深度。

主模型协调结果，必要时裁决有证据的误判，不重复逐项全面审查。实际阻塞项交原编码代理修复，保持编码强度；优先用本轮工具支持的 follow-up/resume 接口，不假设可以原地改变型号或强度。代理无法恢复时才重新提供任务与历史尝试。

**初次实现不计轮次；一次修复加一次独立复验是一轮，每个任务最多两轮。**复验只检查原问题、修复及其影响。跨代理、任务重命名、上下文恢复和最终检查不重置计数。第二轮仍有实际阻塞项时停止整个流程，报告问题、尝试、证据和已有成果；等用户决定升级。不得自动升级编码 / 任务验收的模型或强度、由主模型接手编码或把真实缺陷标为完成。

有 ledger 时，在修复派发前预记本轮 `fix_rounds` 和 `FIXING`，修复完成改为 `REVIEW`；同轮复验不再次加一。中断恢复继续当前轮，不重发仍运行的工作。阻塞或中断保留记录；全部验收、整体检查与已授权收尾完成后才清理本次临时目录，细则见编排参考。

## 5. 主模型最终整体检查

仅当用户明确要求，或本次改动有具体的安全 / 权限、并发 / 事务一致性、破坏性数据迁移、公共接口不兼容风险时，全部任务验收通过后，另派一个区别于全部 Coder 和任务 Reviewer 的干净上下文做**独立整体终审**，并记录触发依据。普通页面、样式、兼容接口新增和常规前后端联动由主模型整体检查；任务多、代码量大或存在一般接口依赖本身不触发额外终审。

终审使用当前会话同一精确型号，默认思考强度低一档，最高不超过会话当前强度；材料充分但终审仍明确报告判断困难时，允许按 adapter 自动升到该上限一次。输入、困难判断与复验按 [角色契约](references/roles.md)；终审范围冻结写入，覆盖累计改动和跨任务实际行为，复用有效验收与测试证据。思考升级不更换型号、不重置代码修复预算。

所有任务通过后，当前主模型核对实际累计改动，完成一次整体检查：总需求是否遗漏、跨任务接口与行为是否衔接、是否混入范围外修改、验收与验证证据是否对应最终代码。已验收任务的内部实现复用独立验收结论，有具体疑点或后续代码变化时才检查受影响部分。单任务无跨任务联动时，终审核对需求、范围和最终版本即可。终审发现问题交回编码代理，使用相应任务剩余修复次数；修复后只复核受影响范围。未明确归属的新问题作为新发现记录，不能给同一问题重开预算。

通过后按目标项目授权与规则执行 Git 收尾，本 Skill 不额外授予提交、推送、发布或全局写入权限。最终报告实际结果、验证与未完成项。执行中定期给出简短进度，不能只在后台派发后长时间无输出。
