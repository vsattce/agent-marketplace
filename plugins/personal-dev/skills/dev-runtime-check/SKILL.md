# 远端运行诊断

仅在用户明确调用 `$personal-dev:dev-runtime-check`（Codex）或 `/personal-dev:dev-runtime-check`（Claude Code）后使用。普通故障描述、日志或性能问题不会自动启用本 Skill。

## 确认目标与授权

先从当前对话确认 SSH 连接方式、目标主机、目标服务或容器、症状和大致时间范围。信息足以连接并确定检查对象时，直接开始必要取证，不再要求重复确认。只有连接目标、认证方式或诊断对象缺失且无法从上下文判断时，集中询问一个关键问题。

默认只做诊断。不要因此清理数据、重启服务、安装工具、修改生产配置或启动持续采集。用户明确要求修复时，在该目标和已授权范围内完成必要更改及受影响验证；不要把调用本 Skill 当成扩大权限的依据。仍遵守 Harness 的权限、审批和组织控制。

## 使用当前 Harness 的原生工具

仅支持 Codex 与 Claude Code。由当前模型使用当前 Harness 可用的 Shell / 终端工具和已有 SSH 配置、Agent 或密钥：Codex 使用其当前可用终端执行能力；Claude Code 使用原生 Bash 工具。不要把一个 Harness 的参数、Python helper、子代理或客户端命令要求套到另一个 Harness；默认不委派、不嵌套启动客户端。

连接信息与诊断目标明确后，使用有限连接超时直接连接，并为每条远端命令设置有限执行超时；按当前 Harness 工具支持的方式实现。连接或命令失败只在适用的暂时性故障下有限重试，不无限等待或循环重试。Linux 目标的只读起始示例：

```sh
ssh -o ConnectTimeout=10 <user>@<host> 'hostname; date -Is; uptime'
```

按目标操作系统选择后续命令。复用已有安全认证机制；如需交互认证，只使用当前 Harness 可用的安全交互输入，不把秘密写进命令参数、源码、报告、回显或 Git。不要记录密码、私钥、Token 或完整环境变量。不要为取证安装监控套件、开启长期采集、压测第三方服务或进行全盘扫描。只有相关命令确实需要更高权限、当前工具有权使用且授权覆盖时，才运行单条必要的 `sudo` 检查。

先确认远端主机名、操作系统、时间与运行时长，再核对目标进程、服务或容器身份。使用目标主机上的证据；如果 SSH、权限或工具失败，说明失败阶段和缺失能力，停止远端结论，不改查当前工作站冒充目标证据。用户提供了日志但无法连接时，可分析这些日志，并明确哪些远端事实仍未知。

## 按症状收集有限证据

从最小证据开始，根据结果再深入。命令限定目标、时间窗口和输出行数；采样限定持续时间与次数。命令不存在时说明限制，使用已有的相关证据，不自动安装替代工具。

- **CPU、内存或长期运行：** 同时确认主机与目标进程或容器的范围。需要速率时读取两次计数并记录真实间隔；单次快照说明当前状态，不能证明增长趋势。区分短时尖峰、持续负载和进程启动时间。
- **磁盘空间与 I/O：** `df` / 定向目录检查反映空间占用；两次 I/O 计数之差除以实际间隔才是采样速率。区分宿主机设备、容器限制或统计、应用写入和实际设备写入，不用应用写入量代替主机磁盘写入。
- **网络与请求：** 按需比较目标网卡或进程的两次计数，记录间隔并处理重启、计数回退。排查请求量时区分浏览器到自有后端和后端到第三方服务；用相关服务、时间窗内的日志或已有指标，不扫全量日志。
- **日志与部署：** 只读取目标服务和症状时间窗内的有限日志；查看必要字段，避免输出凭据或敏感数据。部署与故障时间相邻只是相关性，除非有直接证据，不把时间相关写成因果。

比较累计计数时保留前后读数、实际间隔和单位。发生重启、进程替换、容器重建或计数回退时，丢弃跨边界速率并重新采样。报告采样次数，不从单次累计值推导速率。

## 汇报诊断结论

明确写出目标主机与对象、目标本地时间范围、命令或数据来源、单位、采样间隔和关键数值。将直接观察到的事实、已确认原因与待验证推测分开；说明连接失败、缺少权限或采样限制，以及已执行的操作。给出与证据相称的下一步，不把未验证的推测表述成根因。
