# 按需实现

仅在用户明确调用本 Skill 后使用。Codex 调用 `$personal-dev:dev-yagni`，Claude Code 调用 `/personal-dev:dev-yagni`；普通请求、引用调用名或讨论 Skill 都不触发它。

## 确认当前要做什么

结合完整对话判断用户是在要求执行、只看方案，还是暂缓修改。“先看方案”“先讨论”“暂时不要执行”等明确要求优先：说明目标、最小方案和会实质影响结果的取舍，然后等待确认。用户明确调用本 Skill，目标清楚且没有要求只读讨论或暂缓修改时，默认由当前模型直接执行，不再要求一次额外批准。只有 Skill 名称而没有清楚的开发目标时，只问一个关键问题，不自行补造需求。

只处理当前调用指向的项目和任务，不跨项目、不修改全局配置；任务结束或用户明确更换任务后，本 Skill 的约束不继续延用。先读该项目的规则、需求和直接相关实现，按当前目标、范围与约束实现最小但完整的结果。遵循现有接口、数据契约、技术栈和项目写法；不增加未来假设、无实际用途的抽象、配置、扩展点或功能，也不借精简之名撤销已确认的需求或改动范围外内容。

按真实适用性优先复用项目已有能力和依赖，再考虑标准库或成熟的第三方依赖。需要引入新依赖时，按项目规则说明必要性、替代方案与维护代价；安装或升级依赖按当前任务已有授权和项目规则处理，不得仅因调用本 Skill 就操作依赖。必要的校验、错误处理、安全、权限、事务、并发控制、资源释放和可排查性不能为少写代码而削弱。遇到会实质改变结果且无法从项目或对话判断的问题，再集中询问一次。

按改动风险运行直接相关的验证，核对最终差异，说明实际改动和未能验证的部分。调用本身不扩大 Git、依赖或发布权限；这些操作按目标项目规则和当前任务已有授权处理。

## 用户明确选择委派时

不默认派生代理、不自动调用其他 Skill。若用户在当前任务中明确选择 `dev-delegate`，将本 Skill 已启用的约束、已确认方案、授权范围和验证条件交给既有委派流程；任何方案确认要求继续有效，不能由委派绕过。
