# 角色交接与验收契约

所有角色服从目标项目规则、当前用户授权和本 Skill 的模型选择、修复上限。禁止派生子代理、擅自升级模型、修改全局配置或自行 commit / push。

## 编码代理

主模型提供：

- 工作目录、目标、允许修改范围、原有用户改动与基线。
- 必要接口、相关调用点、已有关键决策和约束。
- 可逐项判断的验收条件、适当的验证要求。
- 多步骤任务的记录/报告路径（若有），不得要求读取全部聊天历史。

代理完成实现、自检并按项目规则验证。上下文不足用 `NEEDS_CONTEXT`，确实受阻用 `BLOCKED`，完成但有疑点用 `DONE_WITH_CONCERNS`，其余用 `DONE`。完成声明包含：改动文件、行为变化、实际验证命令与结果、未验证项及理由、疑点。不得用空 TODO / 伪实现冒充完成。

迭代仅执行与改动相关的检查，项目要求或真实风险需要时才跑完整检查。遵守对应运行时约束；不为 Agent 工具安装/切换项目运行时或修改 PATH。

## 独立验收代理

主模型提供同一任务要求、实际改动证据（含新增文件与未提交改动）、编码报告与验证证据。按 Harness adapter 选择验收策略：Codex 默认同型号 `max`，Claude Code 沿用当前子代理配置。新建干净上下文，只读审查；需要有副作用的验证时先报告，由主模型按项目授权安排。

一次审查同时输出：

1. **需求：** `PASS` / `FAIL` / `UNVERIFIED`，逐项识别遗漏、误解、额外实现。
2. **质量与正确性：** `PASS` / `FAIL` / `UNVERIFIED`，检查实际实现、直接调用关系和相关边界。
3. **阻塞项：** 每项给文件/行号、触发条件、实际影响、证据与建议；未确认疑点与确定缺陷分开。
4. **非阻塞建议：** 风格偏好、可选优化与范围外观察单列，不扩大返工。
5. **验证证据：** 检查覆盖真实行为、必要边界和当前代码版本。证据充分则复用，有具体缺口才补针对性检查。未验证项明确说明，不用猜测填成通过。

报告不能只引用编码代理的“测试通过”；核对差异、测试内容及实际输出。相关函数或契约变更时检查直接调用点。不要把审查限制为仅看 diff 而忽略能明确指出的真实风险，也不要无依据遍历整个项目。

`UNVERIFIED` 的必要条件未解决前不能接受任务。主模型可核实缺失证据、裁决审查误判或补充需求，不能以沉默或“可能没事”当作通过。

## 修复与复验

主模型一次交回完整阻塞列表及本任务累计轮次。原编码代理修复并补充受影响验证；独立验收代理逐项输出 `ADDRESSED` / `NOT_ADDRESSED`，检查修复引入的问题和直接影响，不再全项目巡查。新的范围外建议不延长循环。

一次修复和一次复验计一轮，初次实现不计；每任务最多两轮，第二轮仍阻塞时全流程停止。子代理无法恢复或重建上下文不重置计数。

## 主模型整体检查与中断输出

主模型最终读取累计实际改动，检查整体需求、接口联动、遗漏与验证范围，汇总独立审查不能掌握的跨任务风险。完整检查一次；修复后检查受影响范围，不能为了坚持“一次”跳过必要复核。

选择/能力不明确、确定缺陷超限或需要用户升级决定时，中断输出：状态与理由、已完成和未完成工作、实际模型/强度、已尝试的方法与证据、继续所需的明确决定。中断不创建额外代理、不擅自接手编码、不宣称验收通过。
