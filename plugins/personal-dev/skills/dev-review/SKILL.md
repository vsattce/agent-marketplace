# 增强代码审查

Only use when the user explicitly invokes this skill. Codex 使用 `$personal-dev:dev-review`，Claude Code 使用 `/personal-dev:dev-review`，agy 使用 `/dev-review`；不启动原生 `/review`，不嵌套启动客户端。

报告和临时产物按需遵循[任务产物位置](../../references/artifacts.md)；本 Skill 只写审查报告及必要的轻量进度记录，不自动执行 Git 操作。

当前对话主模型负责预检、安排审查与独立复核、核验证据并生成 Markdown 报告。审查代理只读并回传发现，不写文件、不修复、不提交、不继续派生代理。

## 1. 先完成一次预检

确定当前工作目录对应的项目根、适用项目规则、用户指定范围及源码可读性。未指定范围时检查当前项目全部现有自有代码，包括存量、暂存/未暂存修改和新源码；无 diff 也必须检查。指定目录、文件、模块、主题、commit 或 diff 时严格限定报告范围。子目录调用不自动缩小到该子目录。Git 不可用不妨碍源码审查。多仓库或范围确实不清楚时集中澄清一次。

记录只读基线：当前范围、工作区变化、可用 Git 状态以及后续可能影响证据的变化。排除依赖、构建产物、生成文件、历史报告和二进制；只有核实结论所必需时读取相关自有配置或直接调用点。范围外问题只简要注明。

报告默认写到项目的 `docs/personal-dev/reviews/<review-id>/report.md`，按用户时区用日期、时间和主题组成 ID；冲突时追加唯一后缀，绝不覆盖。先检查目录/位置可写。仓库规则不允许默认位置时选合规位置；若报告无法写入，BLOCKED，集中询问用户其他位置或是否接受仅聊天输出。长审查的轻量进度记录放在报告同目录。执行期间只有报告和必要的轻量进度记录可写；代码、配置、Git 状态只读，不自动提交或推送。

派发前从当前会话确认真实 Harness，不能从模型品牌猜客户端。Codex 读取 [Codex adapter](../../references/codex.md)，用本 Skill 的 `scripts/select_models.py` 校验本轮可信主模型身份、实际派发名单与强度；同代最高数值版本 Luna 默认 `xhigh` 审查、`max` 复核，最高版本缺少任一强度时 `BLOCKED`。Claude Code 读取 [Claude adapter](../../references/claude.md)，agy 读取 [agy adapter](../../references/agy.md)；后两者沿用原生子代理模型与思考配置，不运行 Codex helper，不要求 Python 或 Codex 参数。其他或未知 Harness `BLOCKED / UNSUPPORTED AGENT`。

必需项缺失时，在任何正式审查派发前一次性汇总所有已知缺口、理由、需要用户提供的明确内容和已完成工作，标记 `BLOCKED` 并停止。不能以其他模型替代用户指定的策略。Claude 默认配置的实际型号未解析时如实标 `UNKNOWN`，不因此单独阻塞。可选生产权限、凭证、配额、运行环境、实时数据或完整运行证据缺失，不阻塞普通静态审查；明确说明本次为代码层面审查，并将量化/运行结论列为待验证。只有用户明确要求的实测缺少条件才阻塞。

预检成功后，在派发前按 adapter 展示审查与复核两行。Codex 显示 helper 返回的实际型号和强度：

```text
审查模型：<实际型号>｜思考强度：<实际强度>
复核模型：<实际型号>｜思考强度：<实际强度>
```

Claude 显示“Claude Code 子代理默认 / 沿用当前配置”，agy 显示“agy 原生默认 / 继承当前配置”；未确认实际值标 `UNKNOWN`。不可用或结果 `BLOCKED` 时不派发，不宣称已启动；不自动降级、升级，或让主模型替代全部审查。

## 2. 只读检查与派发

明确任务会话工作目录、范围、适用规则、基线、必要参考和禁止事项。按规模及独立调用链分工；小范围只派一个审查代理，默认同时最多两个且服从工具槽位。按对应 adapter 使用已确认的模型策略与原生工具，所有代理使用干净任务上下文，不得继续派生。禁止自动修复、commit/push、安装/升级依赖、切换运行时或全局配置、连接生产、压测第三方、运行有副作用的项目脚本。

审查基础正确性、边界、异常、安全、并发、回归及关键验证缺口。专项标准见 [审查契约](references/review-contract.md)。判断性能、内存、第三方请求、磁盘和长期运行问题时，说明真实可达路径和放大条件；区分浏览器到自有后端与后端到第三方，区分应用写入与宿主机实际磁盘写入。

正常有限缓存、必要日志、合理频率与有限重试不天然构成缺陷；配额未知不能声称必然封禁。无界增长、请求失控等有明确证据时才升级。缺少最佳实践或测试本身、纯风格、命名、格式、“可以更优雅”均不单独报告。

审查代理返回候选发现、证据、触发条件和实际覆盖。另一个独立代理只核验 P0/P1 候选及实质争议，不重做全量扫描；没有候选就跳过并记录。主模型读取直接证据，合并同根因问题，裁决等级、确定性、跨模块影响和覆盖；每项候选最多一轮定向补证。未解决的猜测转为待验证；新硬性条件造成阻塞时停止余下正式派发，记录已有结果，并中断仍在运行的审查代理。

## 3. 分级、报告与结束

按审查契约分 P0–P3，证据独立标记“已确认 / 条件风险 / 待运行验证”。所有真实 P0/P1 必须保留代码位置、可达触发、影响、证据和建议，并经独立复核；未经确认的严重猜测只列观察/待验证。P2 简述，P3 按主题合并。不能为了简短截断真实高等级问题。

报告使用 [报告结构](references/report-template.md)，必须记下范围、基线、主模型及实际审查/复核模型、执行方式、覆盖和遗漏、问题等级、证据状态、复核裁决、待验证项及限制。已覆盖无发现明确写出；不适用与未覆盖分开。审查前后源码基线变化时只复核受影响证据；不能完成则 `PARTIAL`。报告及轻量进度记录不自动 commit/push。

长审查在报告同目录保留轻量进度记录：范围、实际模型、代理身份、覆盖状态、候选与裁决。上下文恢复后读取记录并接续未完成范围，复用已有证据，避免全量重扫。

执行状态独立于问题等级：`COMPLETE` 表示约定范围检查完成，可以包含 P0/P1；`PARTIAL` 表示范围有遗漏或执行失败；`BLOCKED` 表示必需条件需用户补充。发现缺陷不等于执行阻塞。结论只覆盖实际检查的代码与证据，不表示项目绝对安全。最终聊天给状态、重点发现和报告绝对路径。
