# 增强代码审查

Only use when the user explicitly invokes this skill. Codex 使用 `$personal-dev:dev-review`，Claude Code 使用 `/personal-dev:dev-review`，agy / dsh 桌面版使用 `/dev-review`；不启动原生 `/review`，不嵌套启动客户端。

报告和临时产物按需遵循[任务产物位置](../../references/artifacts.md)；本 Skill 只写审查报告及必要的轻量进度记录，不自动执行 Git 操作。

主模型负责预检、派发、核验证据并生成 Markdown 报告。审查代理只读回传发现，不写文件、不修复、不提交、不派生代理。

默认路径：`reviewer → 主模型核验证据 → 输出报告`。小范围或普通审查只派一个 reviewer；多 reviewer 并行、P0/P1 独立复核、长审查 progress / resume 和更重的专项验证仅在实际需要时启用。

## 1. 先完成一次预检

入口首先读取[子代理模型契约](../../references/subagent-models.md)，归一化 `reviewer / review / r / check` 后校验本次显式 `reviewer=<model>:<effort>`，不要求 worker。缺 reviewer 立即中断，提示缺项和正确格式，早于源码审查、报告创建和任何子代理派发。兼容旧调用显式提供的 worker 时仍校验它，但不因此启动执行代理；后续流程确需执行型子代理时才显式要求 worker，并遵守已有权限边界。

入口同时确认真实 Harness，不能从模型品牌猜客户端。Codex 读取 [Codex adapter](../../references/codex.md)，用本 Skill 的 `scripts/select_models.py` 调用共享校验器，以 reviewer 为唯一必填角色，核验实际派发名单和强度。Claude Code 读取 [Claude adapter](../../references/claude.md)，agy 读取 [agy adapter](../../references/agy.md)，dsh 桌面版读取 [dsh adapter](../../references/dsh.md)；后三者按原生 schema 落实相同显式配置，不运行 Codex helper。模型、effort 或覆写能力不支持立即中断。其他或未知 Harness `BLOCKED / UNSUPPORTED AGENT`。

确定项目根、规则、用户范围及源码可读性。未指定范围时检查当前项目全部自有代码，包括存量、暂存/未暂存和新源码；无 diff 也检查。指定目录、文件、模块、主题、commit 或 diff 时严格限定。子目录调用不自动缩小范围，Git 不可用不妨碍审查。多仓库或范围不清时集中澄清一次。

记录只读基线：当前范围、工作区变化、可用 Git 状态以及后续可能影响证据的变化。排除依赖、构建产物、生成文件、历史报告和二进制；只有核实结论所必需时读取相关自有配置或直接调用点。范围外问题只简要注明。

报告默认写到项目的 `docs/personal-dev/reviews/<review-id>/report.md`，按用户时区用日期、时间和主题组成 ID；冲突时追加唯一后缀，绝不覆盖。先检查目录/位置可写。仓库规则不允许默认位置时选合规位置；若报告无法写入，BLOCKED，集中询问用户其他位置或是否接受仅聊天输出。长审查的轻量进度记录放在报告同目录。执行期间只有报告和必要的轻量进度记录可写；代码、配置、Git 状态只读，不自动提交或推送。

必需项缺失时，在任何正式审查派发前一次性汇总所有已知缺口、理由、需要用户提供的明确内容和已完成工作，标记 `BLOCKED` 并停止。不能以其他模型替代用户指定的策略。模型配置无法核验时立即中断，不以 UNKNOWN 或默认配置继续。可选生产权限、凭证、配额、运行环境、实时数据或完整运行证据缺失，不阻塞普通静态审查；明确说明本次为代码层面审查，并将量化/运行结论列为待验证。只有用户明确要求的实测缺少条件才阻塞。

预检成功后，派发前展示已校验的 reviewer 实际型号和强度；审查、独立检查及严重问题复核均使用同一 reviewer：

```text
reviewer 模型：<实际型号>｜思考强度：<实际强度>
```

四端均落实显式配置，不沿用原生默认。不可用或 `BLOCKED` 时不派发、不声称已启动，不自动升降级或由主模型替代全部审查。

## 2. 只读检查与派发

明确任务会话工作目录、范围、适用规则、基线、必要参考和禁止事项。小范围或普通审查默认一个 reviewer；仅范围较大、调用链可独立划分且并行确有收益时才启用多 reviewer，同时最多两个且服从工具槽位，不因文件多机械扩席。按对应 adapter 使用已确认的配置与原生工具，所有代理使用干净任务上下文，不得继续派生。禁止自动修复、commit/push、安装/升级依赖、切换运行时或全局配置、连接生产、压测第三方、运行有副作用的项目脚本。

审查基础正确性、边界、异常、安全、并发、回归及关键验证缺口。专项标准见 [审查契约](references/review-contract.md)。判断性能、内存、第三方请求、磁盘和长期运行问题时，说明真实可达路径和放大条件；区分浏览器到自有后端与后端到第三方，区分应用写入与宿主机实际磁盘写入。

正常有限缓存、必要日志、合理频率与有限重试不天然构成缺陷；配额未知不能声称必然封禁。无界增长、请求失控等有明确证据时才升级。缺少最佳实践或测试本身、纯风格、命名、格式、“可以更优雅”均不单独报告。

审查代理返回候选发现、证据、触发条件和实际覆盖。主模型先读取直接证据，合并同根因问题，裁决等级、确定性、跨模块影响和覆盖。只有发现有依据的 P0/P1 候选或实质争议时，再派第二个独立 reviewer 定向复核，不预先占席、不重做全量扫描；没有此类问题就直接出报告。每项候选最多一轮定向补证。未解决的猜测转为待验证；新硬性条件造成阻塞时停止余下正式派发，记录已有结果，并中断仍在运行的审查代理。

## 3. 分级、报告与结束

按审查契约分 P0–P3，证据独立标记“已确认 / 条件风险 / 待运行验证”。所有真实 P0/P1 必须保留代码位置、可达触发、影响、证据和建议，并经独立复核；未经确认的严重猜测只列观察/待验证。P2 简述，P3 按主题合并。不能为了简短截断真实高等级问题。

报告使用 [报告结构](references/report-template.md)，必须记下范围、基线、主模型及实际审查/复核模型、执行方式、覆盖和遗漏、问题等级、证据状态、复核裁决、待验证项及限制。已覆盖无发现明确写出；不适用与未覆盖分开。审查前后源码基线变化时只复核受影响证据；不能完成则 `PARTIAL`。报告及轻量进度记录不自动 commit/push。

仅长审查确有跨上下文或中断恢复需要时，在报告同目录保留轻量进度记录：范围、实际模型、代理身份、覆盖状态、候选与裁决；普通审查不建 progress。恢复后接续未完成范围并复用已有证据。更重的专项验证仅在具体证据缺口影响结论或用户明确要求时启用，仍遵守只读权限和运行条件，不默认全量执行。

执行状态独立于问题等级：`COMPLETE` 表示约定范围检查完成，可以包含 P0/P1；`PARTIAL` 表示范围有遗漏或执行失败；`BLOCKED` 表示必需条件需用户补充。发现缺陷不等于执行阻塞。结论只覆盖实际检查的代码与证据，不表示项目绝对安全。最终聊天给状态、重点发现和报告绝对路径。
