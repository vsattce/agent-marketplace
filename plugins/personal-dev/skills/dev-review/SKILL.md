# 增强代码审查

仅在用户明确调用时使用。Codex 为 `$personal-dev:dev-review`，Claude Code 为 `/personal-dev:dev-review`，agy / dsh 桌面版为 `/dev-review`。

默认路径：`reviewer → 主模型核验证据 → 输出报告`。主模型负责范围、派发与最终结论；审查代理只读回传发现，不修复、不写文件、不派生代理。报告保存规则见第 3 节。

## 1. 确认参数与范围

先读取[子代理模型契约](../../references/subagent-models.md)，本次显式参数的规范格式为 `reviewer=<model>:<effort>`，同时接受契约中的空白分隔、模型别名和 effort 简写。复用 dev-delegate 的共享解析与校验，归一化后唯一匹配当前实际模型并校验 effort，不要求 worker；额外提供 worker 时同样校验。缺 reviewer 立即中断，提示规范格式；此校验早于源码审查、报告创建和子代理派发。

确认实际 Harness，并读取对应 adapter：[Codex](../../references/codex.md)、[Claude Code](../../references/claude.md)、[agy](../../references/agy.md) 或 [dsh 桌面版](../../references/dsh.md)。Codex 使用本 Skill 的 `scripts/select_models.py` 校验当前工具清单；其他客户端按原生 schema 校验。派发前展示 reviewer 的实际型号和强度，所有审查与复核使用同一配置。模型、effort、覆写能力或必要权限不足时 `BLOCKED`，说明缺口；未知 Harness 为 `BLOCKED / UNSUPPORTED AGENT`。不补默认值、不替换模型、不嵌套启动客户端。

读取项目规则并确定审查范围。未指定时覆盖当前项目全部自有代码，包括存量、暂存/未暂存及新源码，无 diff 也检查；指定文件、目录、模块、主题、commit 或 diff 时严格限定。子目录调用不自动缩小范围，Git 不可用不妨碍审查。排除依赖、生成物、构建产物、历史报告和二进制，只读核实问题所需的直接调用点。仅当项目或范围确有歧义时澄清。

记下源码/工作区基线，供结论核对。缺少生产权限、凭证、配额或运行环境时仍完成代码层审查，将依赖这些证据的结论标为待验证。

## 2. 审查与核证

小范围或普通审查默认一个 reviewer。交代范围、项目规则、基线及只读边界，按 adapter 使用干净上下文派发。仅大范围存在可独立分工且并行确有收益时增加 reviewer，数量服从实际工具槽位。

审查前读取[审查契约](references/review-contract.md)的证据、分级与降噪规则；按任务选择相关专项，不机械逐项执行。审查代理返回候选问题的位置、触发条件、影响、直接证据、等级建议和覆盖遗漏。

主模型读取直接证据，合并同根因问题，确认等级和覆盖。只有发现有依据的 P0/P1 候选或实质争议时，再派第二个独立 reviewer 定向复核；不重扫全范围。证据不足的猜测列为待验证，不当作已确认缺陷。

更重的专项验证仅在具体证据缺口影响结论或用户明确要求时启用，且须满足只读权限与运行条件；不自动连接生产、压测第三方、安装依赖或执行有副作用的脚本。补证以能判断问题是否成立为止；无法取得的证据明确列为限制。

## 3. 报告与结束

按 [报告结构](references/report-template.md)输出 P0–P3 发现、证据状态、覆盖和限制。真实 P0/P1 完整保留并记录独立复核结论，P2 简述，P3 合并同类项；无发现时明确说明实际检查范围。

报告默认在聊天中输出，不创建报告文件或审查目录，不自动提交或推送。只有用户明确要求保存时，才写入指定位置及必要进度记录；未指定位置时使用项目的 `docs/personal-dev/reviews/<review-id>/report.md`，ID、路径与防覆盖遵循[任务产物位置](../../references/artifacts.md)。保存失败时仍在聊天给出报告，说明未完成的保存要求及原因，并请求可写位置。

普通审查不建 progress。仅用户明确要求保存且长审查确需中断恢复时，在报告同目录简记未完成范围、已有证据和代理状态，恢复时接续。审查期间源码变化，只复核受影响证据；无法重新确认的结论列待验证。

执行状态与问题等级分开：`COMPLETE` 为约定范围已检查，`PARTIAL` 为范围、验证或必需交付有遗漏，`BLOCKED` 为必需条件不足而无法继续。发现缺陷或默认聊天输出不降低执行状态；明确要求的保存未完成时标为 `PARTIAL`。最终聊天给出完整审查结果；要求保存时另附报告路径或保存失败说明。
