# 增强代码审查报告

第一行记录执行状态：`COMPLETE`、`PARTIAL` 或 `BLOCKED`。状态描述约定范围是否完成，与问题等级分开。

## 范围与基线

记录项目根、用户指定范围或默认全项目范围、排除项、适用规则、审查开始时的源码/Git 基线及期间发生的变化。指出是代码层审查还是包含已获准的运行验证。

## 参与模型与方式

记录 Harness、当前主模型的可靠身份来源、审查与独立复核的模型策略及可确认的实际型号/强度、派发方式及是否跳过复核和原因。Claude Code 沿用原生默认配置时，无法确认的实际值标 `UNKNOWN`，不冒充精确 ID。仅记录模型元数据，不写秘密。

## 覆盖情况

用表格分别列出已覆盖且无发现、有发现、不适用、未覆盖/失败的模块或审查维度及原因。

## 发现

按 P0、P1、P2、P3 排序。每项写级别、证据状态、标题、代码位置、触发条件、影响、证据和建议；P0/P1 还记录独立复核结论。P2 简述，P3 按主题合并。

## 待验证与限制

列出尚需运行环境、生产数据、配额或外部服务才能确认的量化问题，并说明本次没有完成的验证及原因。不要把待验证猜测写成已确认缺陷。

结尾说明执行状态依据。状态为 `BLOCKED` 时集中列出已知必需缺口、理由、用户需要提供的明确内容和已有成果。报告默认保存于项目内 `docs/personal-dev/reviews/<review-id>/report.md`，或用户指定的唯一位置；使用用户时区生成 ID 并避免覆盖。
