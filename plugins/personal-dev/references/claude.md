# Claude Code 委派适配

仅用于已确认的 Claude Code Harness。使用本轮原生 `Agent` 工具与其真实参数；不运行 Codex 的 `select_models.py`，不要求 Luna、`reasoning_effort`、`fork_turns` 或 Python。

## 默认模型与思考配置

用户未指定覆写时，编码、验收、审查与复核均沿用 Claude Code 当前子代理的模型与思考配置：使用同一通用子代理类型，省略 `model` 和 `effort`，不改环境变量、项目或用户设置。原生子代理默认可能受当前配置或 managed 策略影响，不保证等于主会话模型，也不保证低费用。

派发前展示两行角色信息，如“编码模型：Claude Code 子代理默认｜思考配置：沿用当前配置”和对应的“验收模型”。审查使用“审查模型 / 复核模型”。有本轮可信解析结果时补充实际 ID / 强度；无法解析时明确标记“实际型号 / 强度 UNKNOWN”，不能把别名或默认策略冒充已确认型号。用户已选择沿用默认配置时，这项未知本身不阻塞执行。

用户明确指定型号或强度时，先核对本轮工具 schema、可用模型和有效覆盖；证据不足则集中 `BLOCKED`，不得默默忽略请求、猜映射或切换型号。Claude 的 `effort` 不是 Codex 的 `reasoning_effort`；较新文档中的参数不代表当前工具已支持。已知环境或 managed 限制会替换用户指定值时先报告，不修改全局配置兜底。

`dev-delegate` 的复杂任务先由主模型补齐设计和验收条件；默认配置仍不足时说明能力缺口，按上述明确覆写与授权规则处理。需要独立整体终审时，同样新建通用非 fork 代理，沿用当前原生默认配置并额外显示“终审模型 / 思考配置”；用户指定时核验实际支持。默认型号未知仍标 `UNKNOWN`，不能声称已使用更强型号；任务确需已确认的更强型号而无法满足时集中 `BLOCKED`，不修改配置兜底。

## 原生委派

1. 确认本轮 `Agent` 与通用子代理可用。优先当前声明支持的 `subagent_type: "general-purpose"`；无此类型时只能选择经本轮证实具有所需读写或审查能力的通用类型，否则 `BLOCKED`。不用只读 Explore / Plan 代理编码。
2. 新任务和独立验收使用不同的新代理，提供精简任务提示与项目规则，不复制完整聊天。选择通用非 fork 子代理；若当前接口显式提供 fork 开关，按其 schema 关闭，不猜不存在的参数，不使用继承整段历史的 fork 代替独立上下文。只读验收 / 审查提示明确禁止写文件、修复、提交、派生代理与运行有副作用命令。
3. 默认每次只有一个写入代理；仅 `dev-delegate` 满足其编排契约时可有限并行。只有本轮原生工具明确支持并发且工作区与槽位安全时才使用，缺失或不明则串行；不启用 Agent Teams。验收另开独立代理。记录工具返回的代理 ID / 任务 ID；多任务同步写回 ledger。前台调用等待返回；后台任务按本轮原生完成通知或 task-output 接口读取结果，不按 Codex 工具名轮询。
4. 原编码代理返工使用当前支持的原生继续方式。提供 `SendMessage` 时按真实 schema 将代理 ID 作为 `to`，否则只有当前 `Agent` 声明支持 `resume` 时才使用它；两者都不支持时重建精简上下文。不要向其他用户聊天发消息，不假设恢复时可以改变型号 / 思考配置。累计修复次数不清零。
5. 缺失委派、独立上下文或必要权限时集中 `BLOCKED`，报告已有工作；不嵌套启动 `claude -p`、不启用 agent teams、不安装依赖或修改权限来补能力。

依据：[Claude Code subagents](https://code.claude.com/docs/en/sub-agents)、[Skills 与手动调用](https://code.claude.com/docs/en/skills)。开发验证与实际业务执行分别记录；隔离捕获加载请求不代表已执行真实模型委派。
