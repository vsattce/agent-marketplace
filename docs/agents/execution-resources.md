# 命令、验证与临时资源

供仓库维护入口执行测试、构建、浏览器验证、Shell / SSH 命令或清理临时目录时使用。仅写文档、只读源码检查不启动进程，也不为登记资源创建文件或 ledger。所有操作仍服从目标项目规则和本次授权。

## 命令必须有结束状态

- 启动前确定工作目录和有限执行预算，优先用项目已有耗时与超时；未知时先给测试 2 分钟、构建 5 分钟的排查预算。预算到期先检查输出和进程，只有明确仍在推进才说明依据并延长；不能靠循环等待无限续期。
- 工具的等待 / yield 时间仅决定何时返回，不是命令超时。返回未完成的 session / task ID 时记 RUNNING，退出状态缺失且无法确认时记 UNKNOWN；保留原生命令 ID、工作目录和启动时间，按原生接口取回结果，不能把包装脚本结束、出现测试摘要或没有新输出当作进程已退出。
- 有后台命令时，在现有 PLAN / 进度记录或当前上下文简记 `命令用途、工作目录、session/task ID、启动时间、状态`；需要终止 OS 进程时再记录 PID 与创建时间。交接、压缩或中断前保留未结束项；worker 返回结果必须附这些项或说明已全部退出。
- 失败、超时和取消走同样的资源释放路径：先正常中断本任务命令，再确认其子进程已退出。确认旧命令结束后才重新运行同一验证；测试的定时器、服务、浏览器和文件句柄在失败分支也须释放。无法确认退出时先排查该验证，不继续堆叠测试进程。
- 按实际 Harness 的状态 / 等待工具接续，不用反复 sleep、读同一文件或新开代理代替等待。持续无进展时检查命令、代理或外部条件，明确具体障碍；不按固定间隔生成新的审查任务。

## 复用有效验证

每轮先运行修复及直接影响的测试。完整测试 / 构建用于首次完整实现、影响面扩大、公共契约变化或项目明确要求；同一代码与环境的有效结果可复用。主模型核验命令、退出状态和对应版本后复用 worker 的当前实测，只有证据缺口才补跑；独立 Reviewer 核查证据和行为，不为“独立”重复同一全量命令。修复后的结果只复用于未再变化的相关范围。

## 清理前先释放

1. 清理临时目录或目标项目要求清理的 worktree 前，先完成本次所有命令的状态对账。关闭本次浏览器、测试服务、watcher 和后台命令；自己的终端工作目录切回保留的主工作区。worktree / 分支只按目标项目已有授权处理，不因本契约自动创建或删除。
2. Windows 删除被阻止时，只读核对本次命令 ID、PID 创建时间、父子链及实际工作目录 / 句柄。命令常用相对路径，不能仅靠命令行含目录字符串判断“无占用”。只停止已核实由本任务启动且仍持有目标目录的进程树；不按进程名批量结束 Node、Python、浏览器或用户终端。未知归属保留并报告。
3. 确认已释放后，再按[临时目录清理规则](../../AGENTS.md#任务产物目录)核实路径与执行清理；删除方式及回收站要求服从目标项目规则。保护用户内容、未交付改动和其他任务资源。
4. 清理失败时区分实际的文件占用、只读、权限、路径或执行策略错误；未取得占用证据时报告“原因未确认”，不统一归为 Windows 文件占用。报告准确残留路径、已退出 / 未退出的本任务命令及错误；遵守停止清理规则，不强删或循环重试。
