# Personal Dev 第一版

## 目标与范围

新增自有 Plugin `personal-dev`，首个 Skill `delegated-development` 仅供 Codex 手动调用。优化主模型的费用与额度负担，不承诺总 token 更少或固定额度折算。Claude / Kimi 不注册该 Plugin；现有五个跨客户端 Plugin 不变。

当前对话主模型负责需求、任务安排、必要澄清和最终整体检查；独立编码子代理默认 `xhigh`，独立且同型号的验收子代理默认 `max`。新任务使用干净上下文，修复优先复用编码代理；代理不得再派生代理。按可独立验证的功能或修复点拆任务，同类小改动合并，默认串行写入。

## 模型选择与可见性

- 实际派发工具当前暴露的允许名单是最终可调用依据，网页、模型目录与配置文件不替代它。
- 自动选择需要当前主模型的可靠身份信息：本轮运行时信息或用户明确说明。不能把全局默认配置、历史记录或自报身份当作本轮证据。
- 已确认的编码系列目前是 `gpt-<version>-luna`。自动选择同一大版本内最高数字版本，数字元组比较，不做字符串比较；`6` 与 `6.0` 同版本歧义时中断。
- 主模型 6.1 / 6.2 可以选择 6 Luna；7 代主模型只有 6 Luna 时中断。无法解析主模型、陌生编码系列、缺少支持强度信息、无合格型号或派发不支持覆写时中断，不静默降级。
- 用户明确指定的可用编码型号可覆盖自动选择，包括改名系列，但必须核对工具与 `xhigh` / `max`（或用户指定强度）支持情况。确认仅作用于当前任务；持久纳入新系列需另有明确维护请求。
- 模型选择使用标准库 Python 检查器，输入由主模型根据当前派发工具声明整理；它不发现模型、不连接服务、不验证输入来源真实性、不修改配置，也不拦截原生派发工具。Skill 必须如实提供输入并使用检查结果。
- 开始编辑前，先向用户显示：`编码模型：<实际 ID>｜思考强度：<实际 effort>`、`验收模型：<实际 ID>｜思考强度：<实际 effort>`，随后直接执行，不再要求确认已成功解析的选择。任务中模型或强度变化时重新显示。
- 中断输出状态、具体理由、已有成果及继续所缺的信息；选择失败时不宣称已启动编码。

## 实现与验收

任务交接包含目标、允许范围、相关调用点、约束和验收标准；复杂任务使用文件与轻量进度记录，简单任务不强制文档。编码代理实现、自检并按目标项目规则验证，报告实际命令、结果与疑点。

验收代理只读审查实际改动及相关实现，同时判断需求符合度、正确性、质量和验证证据。首轮尽量完整汇总阻塞项；疑点有具体依据，非阻塞风格建议不扩大返工。证据充分且对应当前代码时复用验证，有具体疑点再运行针对性检查。

初次实现不计修复轮次；一次修复加一次复验计一轮。每个任务累计最多两轮，跨代理、上下文压缩或最终检查均不重置。第二轮仍有实际阻塞项时停止整个流程，由用户决定升级；主模型不得自动接手编码或升级型号。主模型可裁决有证据的审查误判，不能为绕过上限把真实缺陷标成完成。

所有任务通过后，主模型做一次完整整体检查，读取实际累计改动，关注整体需求、接口联动与遗漏。终审发现问题交回编码代理，修复后检查受影响范围；沿用相应任务剩余轮次。通过后按目标项目授权与规则执行 Git 收尾，不自带提交、推送或发布权限。

验证覆盖模型选择成功、未知/跨代/缺少强度等中断、数值排序、用户明确覆写、包装隔离与手动调用策略；以独立子代理场景验证 Skill 行为。隔离 Codex 加载测试验证发现和显式注入，不执行日常全局安装或真实业务项目修改。
